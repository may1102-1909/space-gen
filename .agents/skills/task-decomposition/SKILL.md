# Task Decomposition

Use this skill for multi-step features, refactors, debugging projects, or work that may span sessions.
1. Translate the request into an observable end state and explicit non-goals.
2. Inspect existing code and tests before designing tasks.
3. Split work into small tasks that each produce a reviewable artifact.
4. Mark dependencies and identify tasks that can safely run independently.
5. Define acceptance criteria and the smallest meaningful verification for each task.
6. Order tasks to reduce rework; complete foundational work before dependent tasks.
7. Track unresolved questions and ask only when the answer materially changes scope or risk.
8. Keep the plan proportional to the task; do not create ceremony for trivial changes.
