# Decision Log Adr

Use this skill when choosing architecture, data models, APIs, major dependencies, or cross-cutting conventions.
1. Search for existing decision records and architecture docs first.
2. Record context, decision, alternatives considered, consequences, and date/status where useful.
3. Distinguish facts from assumptions and unresolved questions.
4. Keep the record concise and link to affected files or issues.
5. Update a prior decision when the decision changes instead of leaving contradictory guidance.
6. Do not create an ADR for routine implementation details.
